<Update label="2026-05-26" description="v1.1.0" tags={["feature"]}>
  ## ActivityPub Federation for Content Pods

  Content Pods now have first-class **ActivityPub federation** support. Each pod gets its own Fediverse identity — users on Mastodon, Lemmy, and other servers can follow individual pods and receive new content automatically.

  **Pod Actor Provisioning:**
  - Automatic actor creation during pod setup with gateway-held encrypted keys
  - Exportable key pairs for self-hosted pod migrations
  - `_activitypub` manifest block injected into `manifest.json`

  **Outbox & Content Delivery:**
  - Webhook-driven outbox: publish/unpublish events trigger immediate ActivityStreams delivery
  - Content mapped to `Article` (or appropriate AS2 type) with full metadata
  - `OrderedCollection` pagination for the outbox endpoint

  **Inbox Sidecar (Dynamic Pods):**
  - New `activitypub-inbox.php` dynamic feature handles inbound activities
  - Stores replies, likes, and boosts in the pod's local SQLite database
  - HMAC-authenticated forwarding from the Federation Gateway
  - Queryable via `GET /_dynamic/api/activitypub-inbox.php?content_id=...`

  **Reply Mirroring (Static Pods):**
  - Gateway stores inbound interactions locally for static pods
  - Readable via admin API (`/admin/pods/:actorId/replies`, `/reactions`)
  - Studio and mobile display federated interactions alongside native comments

  **Pod Migration (Move):**
  - Migrate pod identity between hosts using ActivityPub `Move`
  - Bidirectional `alsoKnownAs` verification for security
  - 365-day overlap period keeps old actor live as redirect
  - Full admin API: migrate, status, also-known-as, finalize
  - Documented runbook for self-hosted operators

  <Callout kind="tip">
    Enable the inbox sidecar by setting `activitypub_inbox.enabled: true` in your pod's dynamic features config.
  </Callout>
</Update>

<Update label="2026-04-24" description="v1.0.4" tags={["bugfix"]}>
  ## Pod Hosting — DI & Local Development Fixes

  **BillingService injection failure**

  - `BillingController` used `@Inject('BILLING_SERVICE')` to request a named provider, but `AppModule` registered `BillingService` as a plain class — NestJS could not resolve the dependency and the service failed to start
  - Fixed by registering `BillingService` with the named token: `{ provide: 'BILLING_SERVICE', useClass: BillingService }`

  **JwtAuthGuard — 500 on all routed endpoints**

  - Every HTTP request to the Pod Hosting API returned `500 Internal Server Error` with `this.reflector.getAllAndOverride is not a function`
  - Root cause: `tsx` (used for `start:dev`) uses esbuild, which does **not** support `emitDecoratorMetadata` — NestJS could not infer the `Reflector` type from the `JwtAuthGuard` constructor, so the `Reflector` was never injected
  - Fixed by switching `APP_GUARD` from `useClass` to a `useFactory` provider with explicit `inject: [Reflector]`, ensuring correct dependency injection regardless of transpiler metadata support

  **Local development `.env`**

  - Added documentation and a `.env` template for local development — the Pod Hosting app requires `DATABASE_URL` and optionally `JWT_SECRET` to connect to the `roadbeat_content_pod` database

  <Callout kind="tip">
    When using `tsx` or `esbuild` with NestJS, always use explicit `@Inject()` decorators or factory providers — do not rely on TypeScript reflection metadata for dependency injection.
  </Callout>
</Update>

<Update label="2026-04-20" description="v1.0.2" tags={["feature"]}>
  ## Free Pod Auto-Provisioning (Phase 5)

  New organizations created via the multi-tenant Studio now get a free Content Pod automatically:

  - **Pod mode selection** — `podMode: 'static' | 'dynamic'` on `CreateOrganizationDto`
  - **Auto-provisioning** — `ContentPodSetupService.setupFreeStaticPod()` / `setupFreeDynamicPod()` called during org creation
  - **Quota enforcement** — free tier: 500 MB storage, 200 items; HTTP 403 on exceed
  - **Quota tiers** — free, starter (5 GB / 5K), pro (20 GB / 50K), enterprise (unlimited)
  - **Admin quota management** — `PUT /manage/content-pod/config` accepts `quotaItemCount` and `quotaStorageBytes`
  - **Onboarding status** — `GET /platform/onboarding/status` returns pod config, quota, and usage

  E2E tested: 57/57 pass (static/dynamic provisioning, publish pipeline, quota 403 enforcement)
</Update>
